# Ziad Invoices Professional 3.3.17

## الجديد في 3.3.17 — خط الفواتير 16 + صفحة السلف

- تم رفع حجم خط **البيانات التي يكتبها المستخدم داخل جميع قوالب الفواتير** إلى **16pt كحد أدنى** في شاشة التحرير والطباعة. أي حقل كان خطه أكبر من 16pt يبقى بحجمه الأكبر حتى لا يتم تصغير أي قالب.
- لم يتم تعديل ملفات HTML الرسمية نفسها؛ تغيير حجم خط البيانات يتم من طبقة الربط والطباعة، لذلك تصميم A4 والصور والخطوط الثابتة في القالب تبقى محفوظة.
- أضيفت صفحة مالية مستقلة باسم **سلف** وليست فاتورة. الحقول: **الاسم الثلاثي، المبلغ، الشهر، الملاحظات**.
- يمكن تسجيل **تسديد** جزئي أو كامل للسلفة؛ يخصم المبلغ مباشرة ويظهر المسدد والمتبقي.
- يوجد **مشاهدة، تعديل، تقرير، تسديد، حذف نهائي** حسب دور المستخدم، مع سجل كامل لكل عملية تسديد والمستخدم والتاريخ والملاحظة.
- صفحة **سلف** مضافة إلى صفحة **صلاحيات** ويمكن للمدير تحديد من يراها.
- قاعدة البيانات أصبحت Schema 7 وتضيف `advances` و`advance_payments` تلقائياً عند التشغيل، مع RLS وحماية Supabase نفسها المستخدمة في بقية جداول النظام.
- لا يحتاج التحديث إلى تشغيل SQL يدوي عند النشر العادي على Render.

## الجديد في 3.3.16 — حماية Supabase / RLS

- إصلاح تحذير Supabase `rls_disabled_in_public` للجداول الخاصة بالنظام.
- تفعيل Row Level Security على جداول Ziad Invoices الموجودة داخل `public`.
- سحب صلاحيات القراءة والكتابة المباشرة من `anon` و`authenticated` لأن التطبيق يصل للبيانات عبر FastAPI على Render وليس مباشرة من المتصفح.
- حماية الجداول والتسلسلات الجديدة افتراضياً من نفس الصلاحيات.
- ملف `SUPABASE_SECURITY_FIX.sql` مرفق لتأمين قاعدة البيانات الحالية والتحقق من النتيجة.
- لا يتم حذف أو تعديل أي سجل من بيانات المستندات أو القروض.

## الجديد في 3.3.15 — إصلاح تقرير القروض بدون Pop-up

- زر **تقرير** يفتح التقرير داخل النظام نفسه، ولا يحتاج السماح بالنوافذ المنبثقة في Chrome.
- زر **طباعة / حفظ PDF** يطبع التقرير الحالي مباشرة بقياس A4.
- التقرير يعرض ملخص القرض وسجل التسديدات الكامل.
- لا يوجد أي تغيير في قوالب المستندات الرسمية.


## الجديد في 3.3.14 — تحسين التحويل والداشبورد

تمت إعادة تصميم **صفحة تحويل** كمساحة إدارة احترافية مستقلة: رأس واضح، زر طلب تحويل جديد، بطاقات حقيقية لعدد الطلبات والمحفوِظ والمسودات وإجمالي المبالغ الرقمية، بحث وفلترة حسب الحالة والقسم، وجدول مخصص يعرض **الدفع إلى، الغرض، جهة التحويل، القسم، المبلغ والعملة** بوضوح. شاشة فتح طلب التحويل نفسها أصبحت تملك رأساً ومعلومات مختصرة خاصة بالتحويل، بينما ملف قالب التحويل HTML بقي مطابقاً للأصل byte-for-byte ولم يتغير تصميم A4 أو الطباعة.

تم أيضاً تحديث **الداشبورد** ليصبح لوحة تشغيل فعلية: ترحيب وتاريخ اليوم، بطاقات مؤشرات رئيسية، بطاقة خاصة بطلبات التحويل، حالة كل قسم ونسبة المستندات المحفوظة، آخر المستندات، نشاط آخر 7 أيام، تنبيه للأقسام التي تحتوي مسودات، وملخص القروض من البيانات الحقيقية للمستخدم الذي لديه صلاحية صفحة القروض. لا توجد أرقام تجريبية أو بيانات ثابتة في الداشبورد.

لا يتطلب هذا الإصدار أي Migration أو SQL جديد.


## الجديد في 3.3.13 — صفحة قروض مباشرة + تقرير

صفحة **قروض** ليست فاتورة ولا تستخدم أي قالب A4. الإضافة تتم مباشرة من أعلى الصفحة عبر: **الاسم الثلاثي، المبلغ، عدد الأشهر، المبلغ المحدد**. يمكن تنفيذ **تسديد** فيخصم المبلغ من الرصيد، ويعرض النظام **المبلغ المتبقي والأشهر الباقية**. كما يوجد زر **تقرير** لكل قرض لفتح تقرير عربي قابل للطباعة أو الحفظ PDF مع سجل جميع عمليات التسديد.

## الجديد في 3.3.11 — صفحة القروض والتسديدات

أضيفت صفحة مستقلة باسم **قروض** يمكن التحكم في ظهورها لكل مستخدم من صفحة **صلاحيات**. يحتوي كل قرض على الاسم الثلاثي، مبلغ القرض، عدد أشهر التسديد، والحد الأدنى لمبلغ التسديد.

عند تسجيل أي تسديد، يخصم النظام المبلغ فوراً من الرصيد ويعرض **المبلغ المتبقي** و**الأشهر الباقية**. كل عملية تسديد تحسب شهراً واحداً، وإذا تم تسديد الرصيد كاملاً تصبح الأشهر الباقية صفراً. لا يسمح النظام بتسديد مبلغ أقل من الحد الأدنى المحدد، باستثناء الدفعة النهائية إذا كان المتبقي نفسه أقل من الحد الأدنى.

تتوفر إجراءات **مشاهدة، تعديل، تسديد، وحذف نهائي** حسب دور المستخدم. يحتفظ النظام بسجل كامل لكل عملية تسديد مع المستخدم والتاريخ والمبلغ والرصيد والأشهر بعد العملية.

ترقية قاعدة البيانات إلى Schema 5 تتم تلقائياً عند التشغيل وتضيف جدولي `loans` و`loan_payments` بدون الحاجة إلى SQL يدوي.

## الجديد في 3.3.9 — تحويل وصلاحيات الصفحات

أضيف نوع مستند جديد باسم **تحويل** بالرمز `TR`. يستخدم النظام ملف HTML الذي وفره المستخدم مباشرة داخل `app/static/form-templates/request-transfer.html`، وتتم الكتابة على حقوله الأصلية داخل المحرر مع نفس نظام **ملاءمة / تكبير / تصغير** والطباعة A4.

يحصل مستند التحويل على رقم تسلسلي مستقل مثل `TR-000001`. القالب المرفوع نفسه لا يحتوي على خانة رقم مستند، لذلك يظهر الرقم في واجهة النظام ويحفظ في قاعدة البيانات دون حقنه في مكان غير موجود داخل القالب.

أضيفت صفحة إدارية باسم **صلاحيات**. يستطيع مدير النظام تحديد الصفحات التي يمكن لكل مستخدم رؤيتها:
- الداشبورد.
- مستند قبض.
- طلب صرف.
- مستند دفع.
- كشف صيانة السيارات.
- تحويل.

صلاحية الصفحة منفصلة عن **نوع الحساب**: نوع الحساب `محرر` أو `مشاهد` يحدد ما يستطيع المستخدم فعله داخل الصفحة، بينما صفحة **صلاحيات** تحدد الصفحات التي تظهر له أصلاً. إلغاء صلاحية صفحة يخفيها من القائمة ويمنع الوصول إلى مستنداتها أيضاً عبر API. مدير النظام يمتلك جميع الصفحات تلقائياً.

عند ترقية قاعدة بيانات موجودة، ينشئ النظام جدول `user_page_permissions` تلقائياً. جميع المستخدمين الحاليين يحصلون على الصفحات الحالية مفعلة مبدئياً حتى لا يفقدوا الوصول بعد النشر، ويمكن للمدير بعدها تعطيل ما لا يحتاجونه.

## معاينة القالب والتكبير

يظهر نموذج A4 كاملاً افتراضياً داخل شاشة الإنشاء والتعديل والمشاهدة باستخدام **Auto Fit**. شريط التكبير يوفر **− / النسبة / + / ملاءمة**، ويمكن التكبير حتى 250% للكتابة الدقيقة أو التصغير حتى 50%. التكبير يؤثر على المعاينة فقط؛ الطباعة تبقى A4 بالحجم الأصلي.

## القوالب HTML الفعلية

يوجد الآن خمسة أنواع مستندات فعالة داخل النظام:

- مستند قبض `RV`
- طلب صرف `PR`
- مستند دفع `PV`
- كشف صيانة السيارات `VM`
- تحويل `TR`

القوالب HTML محفوظة داخل `app/static/form-templates/` ويتم التحقق من بصماتها بواسطة `HTML_TEMPLATE_HASHES.sha256`. عند التحرير يفتح النظام القالب نفسه داخل إطار Same-Origin ويربط البيانات بعناصره الأصلية. وعند الطباعة يستخدم Chromium/Playwright نفس القالب والبيانات المحفوظة لإنتاج A4.

قوالب PDF وWord القديمة للأربعة أنواع الأصلية ما زالت محفوظة داخل `templates/` للأرشفة والرجوع. ملف التحويل الذي أضيف في 3.3.9 مصدره HTML فقط، ولم تتم إضافة PDF أو Word غير موجودين أصلاً.

3. شغّل `start-desktop.bat`.
4. في أول تشغيل أنشئ حساب مدير النظام.

## التحديث دون فقدان البيانات

### Render + Supabase

ارفع الكود الجديد إلى نفس المستودع مع إبقاء متغيرات البيئة الحالية كما هي:

- `DATABASE_URL`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_STORAGE_BUCKET`
- `ZIAD_STORAGE_BACKEND`

انتظر حتى يصبح Render بحالة `Live`، ثم نفّذ `Ctrl + F5`.

### نسخة محلية

أوقف التطبيق، خذ نسخة احتياطية، استبدل ملفات البرنامج بملفات الإصدار الجديد، وأبقِ مجلد البيانات الحالي. عند التشغيل ينفذ النظام ترقية قاعدة البيانات تلقائياً.
