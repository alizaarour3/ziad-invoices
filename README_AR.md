# Ziad Invoices Professional 3.3.8



## إصلاح عرض القوالب في 3.3.8

تم إصلاح محرك المعاينة الداخلي للقوالب HTML: طلب الصرف لم يعد يظهر مكبراً ومقصوصاً، ومستند الدفع وكشف صيانة السيارات لم يعودا يظهران كصفحة بيضاء. السبب كان اختلاف اتجاه RTL/LTR داخل iframe إضافة إلى خطأ في التنقل بين حقول الأسطر المتعددة. الإصلاح يغيّر **طريقة العرض داخل المحرر فقط** ولا يغيّر ملفات القوالب الأصلية أو مواضع الكتابة أو الطباعة.

## تكبير وتصغير القالب في 3.3.8

أضيف شريط Zoom داخل شاشة المستند: **− / النسبة / + / ملاءمة**. يبدأ النموذج دائماً بعرض A4 كاملاً داخل الشاشة، ثم يمكن تكبيره حتى 250% للكتابة الدقيقة أو تصغيره حتى 50%. عند التكبير يمكن التمرير داخل مساحة القالب بدون تغيير مقاس الطباعة أو ملفات HTML الرسمية. زر **ملاءمة** يعيد الصفحة فوراً إلى العرض الكامل.

## عرض A4 كامل داخل الشاشة في 3.3.6

عند إنشاء أو تعديل أو مشاهدة أي مستند، يقوم النظام الآن بعمل **Auto Fit** لصفحة A4 حسب العرض والارتفاع المتاحين داخل المتصفح. لا يتم تكبير النموذج فوق حجمه الطبيعي؛ يتم التصغير فقط بالقدر اللازم لإظهار الصفحة كاملة من الأعلى إلى الأسفل. يتجدد القياس تلقائياً عند تغيير حجم النافذة أو إخفاء/إظهار القائمة الجانبية، بينما تبقى الطباعة A4 بالحجم الأصلي 100%.

لا يغيّر هذا التحديث أي موضع أو خط أو عنصر داخل القوالب الرسمية.

## القوالب الرسمية المعتمدة منذ 3.3.5

هذا الإصدار يعتمد القوالب HTML الأربعة التي اختارها المستخدم كواجهة المستند الفعلية داخل البرنامج: مستند الدفع، طلب الصرف، مستند القبض، وكشف صيانة السيارات. الملفات محفوظة كما رُفعت داخل `app/static/form-templates` ويتم التحقق من بصمتها بواسطة `HTML_TEMPLATE_HASHES.sha256`.

عند التحرير، البرنامج يفتح القالب نفسه داخل إطار Same-Origin ويربط البيانات بعناصره الأصلية مباشرة. وعند الطباعة، يستخدم Chromium نفس القالب مع البيانات المحفوظة ويخرجه إلى A4. بهذه الطريقة لا يوجد اختلاف بين شكل النموذج داخل البرنامج وشكل الطباعة ناتج عن إعادة رسم الحقول بواسطة محرك مختلف.

قوالب PDF وWord السابقة ما زالت محفوظة داخل المشروع للرجوع والأرشفة، لكنها ليست محرك العرض الأساسي عندما يحتوي نوع المستند على `template_engine: html`.

## دقة مواضع الكتابة في 3.3.4

تمت معايرة حقول مستند القبض وطلب الصرف ومستند الدفع وكشف صيانة السيارات وفق الصور المرجعية التي حدّد فيها المالك مناطق الكتابة. لكل سطر متعدد موضع مستقل في الشاشة والطباعة، بينما تبقى ملفات PDF وWord الرسمية كما هي دون تعديل.

نظام فعلي لإدارة المستندات والفواتير الرسمية، يعمل محلياً على Windows أو سحابياً على Render مع PostgreSQL وSupabase Storage.

## ما يميز هذا الإصدار

- قائمة جانبية قابلة للإخفاء بالكامل من زر القائمة، وتتحول إلى قائمة منزلقة على الهاتف.
- داشبورد جديد يعرض البيانات الحقيقية من قاعدة البيانات: الإجمالي، المحفوظ، المسودات، المرفقات، الطباعة، الأقسام، وآخر نشاط خلال 7 أيام.
- أزرار مباشرة وواضحة للمشاهدة والتعديل والطباعة والحذف داخل الجداول، دون قائمة «إجراءات أخرى» أو نقرات إضافية.
- حقل حفظ واحد مع اختيار حالة المستند: **محفوظ** أو **مسودة**.
- الكتابة متعددة الأسطر مقسمة إلى حقول مستقلة؛ كل سطر داخل البرنامج يطبع فوق السطر المقابل في النموذج.
- تحسين صفحات الأقسام، المحرر، المرفقات، المستخدمين، سجل العمليات، التقارير، والإعدادات، مع أزرار مباشرة متناسقة في جميع الصفحات.
- دعم فعلي لـ PostgreSQL على Supabase وتخزين المرفقات في Bucket خاص في Supabase Storage.
- ملفات Docker وRender Blueprint جاهزة للنشر.

## القوالب الرسمية

القوالب الأربعة الرسمية موجودة داخل `templates/pdfs/`:

- مستند قبض `RV`
- طلب صرف `PR`
- مستند دفع `PV`
- كشف صيانة السيارات `VM`، ويحتفظ بصفحتيه

لا يعدّل النظام هذه الملفات. يتم حفظ قيم الحقول في قاعدة البيانات، ثم إنشاء طبقة كتابة مستقلة ودمجها في ملف PDF جديد عند الطباعة. يمكن التحقق من سلامة الملفات بواسطة:

```bash
sha256sum -c PDF_TEMPLATE_HASHES.sha256
sha256sum -c ORIGINAL_TEMPLATE_HASHES.sha256
sha256sum -c TEMPLATE_HASHES.sha256
```

## التشغيل على Windows

1. ثبّت Python 3.11 أو أحدث.
2. شغّل `setup-windows.bat` مرة واحدة.
3. شغّل `start-desktop.bat`.
4. في أول تشغيل أنشئ حساب مدير النظام.

ملف الإعداد يثبت المتطلبات المحلية من `requirements-windows.txt`. إذا تعذر فتح نافذة Desktop، يرجع المشغل تلقائياً إلى المتصفح على:

```text
http://127.0.0.1:8765
```

## التشغيل المحلي على Linux أو macOS

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
./start.sh
```

## النشر على Render وSupabase

راجع الملف:

```text
DEPLOY_RENDER_SUPABASE_AR.md
```

الحزمة تحتوي على:

- `Dockerfile`
- `render.yaml`
- `.env.example`
- دعم PostgreSQL في `app/db.py`
- دعم Supabase Storage في `app/services/storage_service.py`
- سكربت نقل البيانات القديمة في `scripts/migrate_sqlite_to_supabase.py`

## التحديث دون فقدان البيانات

### من نسخة محلية سابقة

1. أوقف النسخة القديمة.
2. فك هذا الإصدار في مجلد جديد.
3. انسخ مجلد `data` فقط من النسخة القديمة إلى المجلد الجديد.
4. لا تستبدل `app` أو `config` أو `templates` بملفات قديمة.
5. شغّل `setup-windows.bat` ثم `start-desktop.bat`.

### على Render وSupabase

انشر الكود الجديد مع إبقاء نفس متغيرات البيئة ونفس مشروع Supabase. الجداول والبيانات والمرفقات تبقى في Supabase ولا تحفظ داخل حاوية Render المؤقتة.

## الطباعة

- حجم الصفحة: A4 عمودي.
- اختر **Actual size / 100%** عند الطباعة الفعلية.
- ألغِ **Fit to page** لمنع تغيير مواضع الكتابة.
- مرفقات الصور توضع داخل صفحة A4 دون تشويه.
- ملفات Word تحتاج LibreOffice لدمجها تلقائياً مع ملف الطباعة؛ Dockerfile يتضمن LibreOffice Writer.

## إصلاح العربية في 3.3.4

الإصدار 3.3.4 يجعل محرك الطباعة يعتمد على RAQM مع HarfBuzz وFriBiDi لتشكيل الحروف العربية وربطها وترتيب النص ثنائي الاتجاه بشكل صحيح. صورة Docker تتحقق من هذه المكونات أثناء البناء وتوقف النشر إذا لم تكن متاحة، بدلاً من إنشاء PDF عربي مشوّه. لم يتم تعديل أي نموذج PDF أو Word أو أي إحداثيات للحقول.

بعد النشر على Render افتح `/api/health` وتأكد من أن `arabic_rendering.raqm` و`harfbuzz` و`fribidi` كلها `true`.
