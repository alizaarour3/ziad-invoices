# Ziad Invoices Professional 3.3.3

## دقة مواضع الكتابة في 3.3.3

تمت معايرة حقول مستند القبض وطلب الصرف ومستند الدفع وكشف صيانة السيارات وفق الصور المرجعية التي حدّد فيها المالك مناطق الكتابة. لكل سطر متعدد موضع مستقل في الشاشة والطباعة، بينما تبقى ملفات PDF وWord الرسمية كما هي دون تعديل.

نظام فعلي لإدارة المستندات والفواتير الرسمية، يعمل محلياً على Windows أو سحابياً على Render مع PostgreSQL وSupabase Storage.

## ما يميز هذا الإصدار

- قائمة جانبية قابلة للإخفاء بالكامل من زر القائمة، وتتحول إلى قائمة منزلقة على الهاتف.
- داشبورد جديد يعرض البيانات الحقيقية من قاعدة البيانات: الإجمالي، المحفوظ، المسودات، المرفقات، الطباعة، الأقسام، وآخر نشاط خلال 7 أيام.
- أزرار مباشرة وواضحة للمشاهدة والتعديل والطباعة والحذف داخل الجداول، دون قائمة «إجراءات أخرى» أو نقرات إضافية.
- حقل حفظ واحد مع اختيار حالة المستند: **محفوظ** أو **مسودة**.
- الكتابة متعددة الأسطر مقسمة إلى حقول مستقلة؛ كل سطر داخل البرنامج يطبع فوق السطر المقابل في النموذج.
- تحسين صفحات الأقسام، المحرر، المرفقات، المستخدمين، سجل العمليات، التقارير، والإعدادات، مع أزرار مباشرة متناسقة في جميع الصفحات.
- دعم فعلي لـ PostgreSQL على Supabase وتخزين المرفقات في Bucket خاص في Supabase Storage.
- ملفات Docker وRender Blueprint جاهزة للنشر.

## القوالب الرسمية

القوالب الأربعة الرسمية موجودة داخل `templates/pdfs/`:

- مستند قبض `RV`
- طلب صرف `PR`
- مستند دفع `PV`
- كشف صيانة السيارات `VM`، ويحتفظ بصفحتيه

لا يعدّل النظام هذه الملفات. يتم حفظ قيم الحقول في قاعدة البيانات، ثم إنشاء طبقة كتابة مستقلة ودمجها في ملف PDF جديد عند الطباعة. يمكن التحقق من سلامة الملفات بواسطة:

```bash
sha256sum -c PDF_TEMPLATE_HASHES.sha256
sha256sum -c ORIGINAL_TEMPLATE_HASHES.sha256
sha256sum -c TEMPLATE_HASHES.sha256
```

## الوظائف الفعلية

- إعداد مدير النظام في أول تشغيل دون بيانات دخول افتراضية.
- تسجيل الدخول، قفل الحساب بعد المحاولات الفاشلة، وتغيير كلمة المرور مع إلغاء الجلسات القديمة.
- صلاحيات: مدير، محرر، مشاهد.
- ترقيم تلقائي مستقل وآمن لكل قسم.
- إنشاء، مشاهدة، تعديل، حفظ، طباعة، وحذف نهائي حسب الصلاحيات.
- صفحة مستقلة لكل نموذج تعرض المستندات المحفوظة والمرفقات المرتبطة بها.
- رفع متعدد للمرفقات بالسحب والإفلات، مشاهدة، تنزيل، طباعة، وحذف.
- طباعة النموذج وحده أو مع مرفقات محددة في ملف PDF واحد.
- سجل تعديلات وسجل تدقيق للعمليات المهمة.
- تقارير CSV عربية متوافقة مع Excel من البيانات الحقيقية.
- نسخة احتياطية تشمل قاعدة البيانات، المرفقات، القوالب، خريطة الحقول، وبصمات SHA-256.
- SQLite للتشغيل المحلي، أو PostgreSQL وSupabase Storage للتشغيل السحابي.

## التشغيل على Windows

1. ثبّت Python 3.11 أو أحدث.
2. شغّل `setup-windows.bat` مرة واحدة.
3. شغّل `start-desktop.bat`.
4. في أول تشغيل أنشئ حساب مدير النظام.

ملف الإعداد يثبت المتطلبات المحلية من `requirements-windows.txt`. إذا تعذر فتح نافذة Desktop، يرجع المشغل تلقائياً إلى المتصفح على:

```text
http://127.0.0.1:8765
```

## التشغيل المحلي على Linux أو macOS

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
./start.sh
```

## النشر على Render وSupabase

راجع الملف:

```text
DEPLOY_RENDER_SUPABASE_AR.md
```

الحزمة تحتوي على:

- `Dockerfile`
- `render.yaml`
- `.env.example`
- دعم PostgreSQL في `app/db.py`
- دعم Supabase Storage في `app/services/storage_service.py`
- سكربت نقل البيانات القديمة في `scripts/migrate_sqlite_to_supabase.py`

## التحديث دون فقدان البيانات

### من نسخة محلية سابقة

1. أوقف النسخة القديمة.
2. فك هذا الإصدار في مجلد جديد.
3. انسخ مجلد `data` فقط من النسخة القديمة إلى المجلد الجديد.
4. لا تستبدل `app` أو `config` أو `templates` بملفات قديمة.
5. شغّل `setup-windows.bat` ثم `start-desktop.bat`.

### على Render وSupabase

انشر الكود الجديد مع إبقاء نفس متغيرات البيئة ونفس مشروع Supabase. الجداول والبيانات والمرفقات تبقى في Supabase ولا تحفظ داخل حاوية Render المؤقتة.

## الطباعة

- حجم الصفحة: A4 عمودي.
- اختر **Actual size / 100%** عند الطباعة الفعلية.
- ألغِ **Fit to page** لمنع تغيير مواضع الكتابة.
- مرفقات الصور توضع داخل صفحة A4 دون تشويه.
- ملفات Word تحتاج LibreOffice لدمجها تلقائياً مع ملف الطباعة؛ Dockerfile يتضمن LibreOffice Writer.

## الاختبارات

```bash
pytest -q
node --check app/static/app.js
python -m py_compile app/main.py app/db.py app/services/pdf_service.py
```

الاختبارات تغطي دورة المستند، إنشاء كشف صيانة السيارات، الصلاحيات، المرفقات، A4، الحذف النهائي، النسخ الاحتياطي، قفل الحساب، بيانات الداشبورد الحقيقية، الحقول متعددة الأسطر، وعقد الأزرار المباشرة.

## بنية المشروع

```text
app/
  main.py                    API والعمليات
  db.py                      SQLite/PostgreSQL والمعاملات والترقيم
  auth.py                    الجلسات والصلاحيات
  services/pdf_service.py    الكتابة والطباعة ودمج المرفقات
  services/storage_service.py التخزين المحلي أو Supabase
  static/                    واجهة RTL
config/templates.json        إحداثيات الحقول والأسطر
 templates/pdfs/             ملفات PDF الرسمية غير المعدلة
 data/                       بيانات التشغيل المحلي فقط
 supabase/                   مخطط مرجعي
 tests/                      اختبارات النظام
```
